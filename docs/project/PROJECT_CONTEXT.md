# 项目上下文

EpiLocate 研究肺部 CT 中模型分类决策与空间响应的关系。立项主线依次是弱标签下稳定粗定位、粗区内局部细化、医生核验与修正。可以运行的研究原型是承载手段。临床成效、独立患者泛化和生产就绪需分别验证。

## 当前组成

浏览器经 Vue 工作台、会话网关与 Backend v2 管理病例、输入、异步任务和结果。独立 Worker 领取任务，执行冻结模型或受控研究流程，将结果和资产交回后端。数据库保存关系、状态与归属，对象存储保存内容；存储凭据不进入浏览器。查看器按输入几何显示 CT 和响应，不把热图当作分割真值。Welcome、展示站和旧人工复核服务具有不同用途与访问模型。

研究模块保留冻结分类基线、三尺度遮挡响应、稀疏空间比较、验证协议与生成测试。新快照另含可独立运行的 P2 路由模块和一组 ROI 实现摘录。P2 的生成示例走同一候选逻辑，并没有调用医疗模型；ROI 摘录不自动成为主应用的部署版本。公开的字段和协议描述不能用作数据授权。

## 如何判断完成

- **工程。** 源码、局部测试、固定版本端到端、目标环境部署与长期运维分别记录。历史合成 CPU/GPU 工作流完成过；早期跨设备数值一致性出现过失败，后来 D10 的通过仅适用于其指定冻结运行时和合成参照。
- **科研。** 盲评前应锁定输入、干预、分母和缺失规则。分类标签、病例分组、掩膜监督和人类参考必须说明来源。一次真实技术执行、离线缓存比较或代理组开发表现各自回答不同问题。
- **医院协作。** 需求交流和可操作界面属于准备。医院数据使用、独立标注、前后测量和临床结论分别需要可审计的前提与结果。
