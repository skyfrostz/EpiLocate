# EpiLocate 项目迭代史

本表依据原受版本控制的阶段史和后继工程记录整理；日期为当时记录的归档或验证日期。它说明项目如何从离线研究演进为多个独立应用和受控研究工具。各阶段的通过结论仅适用于所列输入、版本和环境。

| 日期 | 设计或交付变化 | 当时能够确定的结论与遗留事项 |
|---|---|---|
| 9/22 | 建立 DICOM 整理、Series 检查、预处理、训练和离线分类基线。冻结 Rule B 系列筛选，与人工复核决定分开保存。 | 可追溯到选定系列与训练划分。来源代理标签不对应逐切片病灶真值，不能把未评区域当阴性。 |
| 9/23–25 | Gradio Mock 先验证交互和接口形状；另行形成用于人工系列决定的复核服务，以及独立的项目展示站。 | 原型、人工复核与在线推理是三个入口；展示成功不证明推理或跨账户授权成功。 |
| 9/25–26 | 研究线冻结 Stage 1 验证、三尺度遮挡与独立技术检查；P0 算法服务接入真实单切片计算。 | 三尺度全图响应成为模型行为的参照。冻结科研记录与产品分支分开，不能把候选响应当作病灶标签。 |
| 9/26 | P0 前后端、任务和几何展示形成统一链路，由独立 QA 在固定版本检查 HTTP、浏览器、权限、文件与冻结哈希。 | 当时的发布验证通过；未覆盖后来 v2 数据库、独立设备和生产运维。 |
| 9/26–27 | 后端升级为 v2，Worker 从请求进程独立运行；Vue 取代单一演示入口，病例、任务、结果和资产按契约关联。 | 分离了界面会话、业务权限和 Worker 身份。生产型数据库与对象存储需要独立往返检查。 |
| 9/27 | 增加凭据生命周期和所有权控制，校验迁移、拒绝路径及 Worker/用户身份边界。加入 CPU、CUDA、AUTO 设备选择及固定 CPU 回归。 | 当时的真实 CPU 链路产生预测、三尺度响应和资产。设备可选并不等于所有设备的数值或性能已通过。 |
| 9/27–28 | 将响应层与 CT 按几何映射显示。先做标记点单测和浏览器缩放、平移、刷新，再复核后端、Worker、前端与存储共同工作。 | 功能与几何验收覆盖指定合成或受控输入，未证明真实病灶重叠。 |
| 9/28–29 | Phase 5 增设受管会话入口与独立计算节点。合成单切片先通过本地 CPU，再通过 PostgreSQL、对象存储、远端 RTX 3090 与浏览器的完整链路。 | 预测与遮挡功能能完成。固定 CPU/GPU 派生数值的最大差 0.001049876，高于冻结容差 0.0001。将功能通过与数值失败分列。 |
| 9/28–29 | 排查 JPEG Lossless 输入的解码依赖问题；运行时修复后新建任务成功，既有失败任务保留原状态。交接资料开始区分运行时、发布身份和长效运维。 | 修复适用于当时环境。干净节点依赖、受管重启及异机数据和对象恢复仍需验收。 |
| 9 月下旬 | 形成源码来源表，按文件导入欢迎页，受限运行证据留在原处；修复浏览器欢迎页，记录计算节点释放及交接分流。 | 没有把内部工程、研究和运营分支整体并入公开历史。历史节点曾通过或后续停用均不证明现网状态。 |
| 10/1–2 | 首轮处理会话恢复、跨页状态及查看器缓存，随后重新组织医学影像工作台布局。前端按独立资源包发布与验证。 | 合成浏览器流程与未登录线上入口各有证据。前端更新并未重验后端、远端真实模型与医生使用。 |
| 10/3–4 | Clinical Canvas 形成整站候选。生产构建的本地预览接入真实 Gateway、Backend、SQLite 和测试存储，并用 Mock API 检查正向结果展示。 | 14 个真实本地场景与 10 个 Mock 场景回答不同问题。实际本地测试库没有 Worker 和正向 Result；只有另一个冻结组合完成过合成输入的真实 CPU 全链。 |
| 10/7 | 按文件整合 Clinical Canvas、会话/幂等处理、Worker 安全诊断与 D10 离线工具。D10 记录在其指定合成参考、冻结模型及指定运行时通过数值门槛。 | 旧 Phase 5 的差异记录仍保留。旧主线整合没有启动新一轮 GPU、生产或真实科研验证。 |
| 10/14–17 | 经筛选纳入数据、编码器、定位、系统集成四线的源码、协议和生成检查，并明确首个来源配对的空间资格限制。 | 一组 20 个已观察来源组上的开发 AUROC 为 0.95；资格失败的来源没有可评空间分母。后续其他来源的受限真实 Dice 另计。 |
| 10 月下旬 | 开发有限预算路由、固定 K8 空间评价、研究 ROI 版本与显示机制。一次真实受控技术执行完成，随后计划的两臂先导仍为 0/2。 | 固定采样域及掩膜监督的结果只支持该限定比较。缓存重放、一次技术成功和请求登记均不能替代独立同预算科学对照。 |
| 10/29 | 整理竞赛材料、手册及图表，把冻结结果、工程证据、生成示意和计划模板分开。 | 图表重排未产生新训练、病例或临床评价；较早文稿的执行状态需与后继记录对照。 |
| 11/3 | 形成独立公开快照，按文件纳入应用、研究工具、聚合结果、生成原型、P2 可移植路由及 ROI 摘录；整理六周计划审查。治理整合恢复工程史、源码分布和冻结边界的公开说明。 | P2 可在生成输入上运行；ROI 摘录原始几何用例 2 项中 1 项失败，外围应用与迁移链不全。公开治理整合属于文档维护，不新增服务部署、模型运行、科学验收或临床结果。 |
