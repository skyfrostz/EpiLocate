# 工程文档维护指南

[迭代史](ITERATION_HISTORY.md)记录为什么形成当前结构、每个阶段交付了什么及下一道门槛。[工程日志](ENGINEERING_JOURNAL.md)记录某日对确切版本做过的工作、输入、验证范围、失败与遗留事项。两份文档互补，不能代替接口合同、研究协议或部署回执。

源码、实质性测试、配置、迁移、运行时及验收变更须同时更新两份记录。纯文档修正可以单独交付，明确引用的原始日期并更正后来状态，不覆盖历史失败。Git 来源、已执行的测试或验收材料，优先于 README 摘要或口述；不能从提交时间猜测操作者或实际执行时间。

| 记录字段 | 要求 |
|---|---|
| 版本与环境 | 记录公开提交或有明确指向的标签、运行环境与依赖条件。仓库外证据只给可审查的范围描述，不暴露内部引用、人员或路径。 |
| 输入、输出与分母 | 区分生成输入、缓存回放、单次真实技术执行和科学验证；给出所有预定臂/样本是否执行、空值和拒绝原因。 |
| 结论 | 区分实现、测试通过、已整合、已部署、科学结果与临床结论。未执行写明“未运行”，不能以零分或成功代替。 |
| 复核方式 | 列出命令、所需条件及通过/失败/跳过。受限资产不公开时明确复现上限。 |

审查当前工作树可运行 `python3 scripts/check_project_documentation.py --base HEAD --working-tree`；审查提交范围使用实际基线 `python3 scripts/check_project_documentation.py --range <base>..<head>`。另运行 `git diff --check` 并检查暂存路径。检查器判断更新范围，不替代对数字、结论、权限和内容安全的人工审查。
