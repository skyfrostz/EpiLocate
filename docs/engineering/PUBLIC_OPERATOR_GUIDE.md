# 公开版工程验收手册

以下步骤供开发者在隔离环境检查入口和证据范围。重建一个能接收真实业务的部署还需要确定完整版本组合、资产授权和独立验收。仓库未提供真实账户、权重或医疗输入。

## 先验证可独立运行的部分

1. 在 `research/portable-p2/`，用 Python 3.9 及以上执行 `python3 -m unittest discover -s tests -v`，再执行 `python3 demo.py`。这两步检查确定性生成分数及每臂的查询预算，不产生医学评价。
2. 按各自锁文件在 `frontend/` 与 `apps/landing/` 执行 `npm ci`。前端可运行 `npm test` 与 `npm run build`；欢迎页运行 `npm run build`。检查退出状态、依赖版本及构建目标；已有页面原型不代表后端已经启动。需要安装依赖时使用项目认可的软件源。
3. 在装好项目相应 Python 依赖的环境，选择模块运行，例如 `python3 -m pytest -q session_gateway/tests/test_gateway.py tests/test_worker/test_protocol.py`。后端数据库或深度学习依赖可能属于不同运行环境，应记录每次用的解释器与输入。
4. ROI 源码摘录提供 API、数据模型、迁移及前端几何逻辑的阅读样例，缺外围依赖与完整迁移链。不能作为当前后端的可直接安装插件。[ROI 说明与已知测试结果](../../research/source-excerpts/r168-roi/README.md)

## 完整环境的分项验收

| 环节 | 核查动作 | 留存证据 |
|---|---|---|
| 配置与构建 | 固定前端、后端、网关、Worker、依赖和 schema 版本；建立隔离的数据库与对象存储。 | 公开版本标识、配置项名称、安装与构建结果。凭据留在运行环境。 |
| 网关与权限 | 用生成账户检查会话、登出、过期处理和跨账户拒绝。 | 允许/拒绝的动作、状态与测试环境，不记录令牌。 |
| 任务与持久化 | 用生成输入检查创建、队列、租约、成功与失败行为，核对结果、资产及幂等重试。 | 预定任务数、实际执行数、错误与资产计数。真实推理需另有可加载、授权且有版本绑定的模型。 |
| 查看器与编辑 | 对照已知生成坐标进行缩放、平移、切片、保存、冲突和刷新。 | 源几何、目标几何、允许误差、失败用例及持久化后结果。 |
| 可恢复性 | 在隔离目标上同时恢复数据库和对象资产，核对版本、引用完整性、受管重启及回滚。 | 实际恢复报告。存在备份文件或运行中的旧进程不足以证明能恢复当前版本。 |

历史前端、CPU、GPU、数据库与生成输入的验收环境不同。请按[工程日志](../project/ENGINEERING_JOURNAL.md)中的范围引用，不合并成不存在的一次全栈通过。
