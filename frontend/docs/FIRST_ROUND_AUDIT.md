## 修改清单与页面审计

严重程度：P1 为账号隔离或流程中断；P2 为状态不清楚、恢复困难；P3 为视觉与易用性问题。以下接口依赖均使用既有 `/auth` 和 `/api/v2` 路径。

| 页面/模块 | 触发条件与原问题 | 级别 | 本轮处理 | 接口依赖 |
|---|---|---|---|---|
| Login / 全局会话 | 退出、401 或账号切换后，旧请求可能写回病例、任务、结果或影像 | P1 | 会话版本校验、同步清理 store/本地偏好、取消请求与轮询、释放 Blob URL；旧登录/退出响应不影响新会话 | session/login/logout；401 |
| Case | 快速切病例、退出页面、上传/建任务迟到响应指向旧病例 | P1 | 页面与病例版本核对、AbortController、清空预览与文件选择；有效成功后更换任务幂等键 | Case detail/upload/Jobs/DICOM |
| Case / Viewer | 加载、空白、输入过期及解码失败混在一起，加载提示可能残留 | P2 | 区分取回、解码、空白、过期、失败、可显示；本地重试；清空文件时释放 renderer | DICOM GET；INPUT_EXPIRED |
| Job | “Job failed.” 过于笼统，FAILED 与完成路径不清晰 | P2 | 中文状态与独立失败说明；保留 Job ID；过期输入引导新病例，推理失败引导维护者与病例页显式新建任务 | Job status/error/failure_reason |
| Job | 查询超时或网络失败使任务真实状态难以判断 | P2 | 保留最近已知状态，明确这是查询失败，提供重新查询；没有自动重跑推理 | Job GET；HTTP/网络错误 |
| Login / API | Backend、Gateway code-only、422 detail、非 JSON 等错误体不同，原始异常可能直接呈现 | P2 | 共用错误归一化，稳定码中文提示，未知错误通用提示与可用请求编号；不直接呈现服务端原始异常 | HTTP status/code/request_id |
| Result / Heatmap | 快速切尺度或图层，旧图片加载事件可能覆盖最终选择 | P1 | 元数据/资产请求版本核对、旧请求取消、图片事件源核对；保留 CT 视角 | Result metadata/assets |
| Result / Heatmap | 缺图、候选不足、资产加载失败不易区分 | P2 | 分别说明，资产与 CT 独立重试；输入过期时仍保留可用独立热图 | authorized asset metadata/GET |
| Viewer / Heatmap | 摘要大小写与几何不匹配使叠加不可用 | P2 | SHA-256 大小写统一；保留严格几何门控；校验失败关闭叠加并说明，独立热图继续可用 | slice/hash/geometry metadata |
| Dashboard | 首页为静态工作入口，无真实统计 | P3 | 审计记录；本轮保持布局和实际能力一致 | 当前无聚合统计接口 |
| 全页面 | 移动端信息密集、字号偏小、Result 页面较长 | P3 | 390 px 移动端及 1100 px 平板验收；长 ID 无横向溢出，导航可收起；重排留到下一轮 | 无新接口 |

不自动重试 `INFERENCE_FAILED`，不伪造 Result，不调用旧 Mock API。用户可以保留失败任务，并在服务恢复后回病例页显式创建新任务。
