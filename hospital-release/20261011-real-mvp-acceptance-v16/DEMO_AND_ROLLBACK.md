# 演示流程与回退｜真实开发 MVP v16

本包是已执行收据的交付入口，不是新的执行授权。`COMMAND_RECEIPT.json` 记录已用过的唯一命令，不能复制重跑或重用原目录、job、任务预算。原自有服务已经退出。

1. 总控提供医院正式 allowlist、模型/预计算资产及精确 SHA；沿用 DATA 唯一清单，不从当前三 SOP 开发 ledger 创建第二份医院清单。
2. 固定代码、既有环境、算法版本、数据与空间变换链；六项真实空间检查通过后才入候选。算法对照入口见 [v1 README](../20261009-integration-v1/README.md)，接口与对照继承原包，独立保留 E1/E2/F0/F1 标识。研究切换 flag 接缝尚未安装为生产 endpoint，不承诺前端已有四算法在线切换。
3. 获准启动时由总控唯一串行调度。原页面上传原始脱敏 CT → 选择已批准算法 → 等待明确状态 → 检查对应影像与响应 → 保存 → 刷新读取已有结果。保留现有 FrozenBaseline 和 16/32/64 控件，不用刷新产生新推理。
4. SUCCESS、NO_RELIABLE_RESPONSE、PARTIAL_BUDGET、FAILED、BLOCKED、NOT RUN 分开显示/记录。无可靠响应不解释为正常 CT；失败或未知事务先核对 JobAttempt、Result、对象 SHA，不盲目再提交、重算或杀身份不明进程。
5. 同一实际医院配置连续三次演示，保存命令、日志、结果与空间证据。备用预计算与录屏各保存 SHA，并有读取/播放检查。当前 v16 实际三条是开发流程；医院这一步仍 NOT RUN。
6. 10 月 14 日首席算法工程师汇总此包及后续验收，交钟佳桦通过当前会话明确批准。未获批、空间验证缺失或无合格备份则 NO-GO，不自动部署或外传影像。

回退：停止新算法新增准入，保留其所有历史结果和失败/partial，不覆盖旧资产；按原 [v1回退步骤](../20261009-integration-v1/DEMO_AND_ROLLBACK.md) 生成新的不可覆盖选择记录，回到已有旧版 FrozenBaseline/Occlusion。研究选择记录本身不能更改生产路由。医院回退仅使用该次展示已批准且空间验收通过的旧版或预计算资产；本次本机开发 PASS 不授予医院显示权限。无合格可用版本时暂停展示并交负责人决定。

真实 run、supervisor、finished、SQLite 和截图位置/哈希由本包 manifest 指向忽略目录的 private-audit；在获准本地环境保管，不把认证文件、原 CT、患者截图或逐患者输出复制到 Git/云盘。负责人需要实际影像审阅时仍通过其获准本机查看流程，本包不发出外传授权。
